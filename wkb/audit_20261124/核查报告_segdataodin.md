## 2. 深度编码核查 —— 结论：正确

### 2.1 判断依据

**① 容器与位深正确**
`uint16` / `mode=I;16` / 1600×1296，无 gamma、ICC 等影响数值的元数据。取值域满量程使用，相邻最小间隔恒为 1 LSB，低 8 位的 256 种取值全部出现 → 可排除"存分块索引 / 百分比"之类的伪编码。

**② 尺度倍率 = 256（每 LSB = 3.906 mm）**
用地面平面对 `Z` 做约束：路面点必须满足 `Z·(v−v0)/A22 = h`（相机离地高度为常数）。四种尺度假设下的 `h`：

| 假设 | h 中位 | 物理含义 | 判定 |
|---|---|---|---|
| **÷256（m）** | **0.524 m** | 低安装位车载/农机传感器 | ✅ 合理 |
| ÷512 | 0.262 m | 26 cm，低于任何量产安装位 | ✗ |
| ÷1000（mm） | 0.131 m | 13 cm，不可能 | ✗ |
| 当 mm 用 | 144.7 m | 不可能 | ✗ |

量程交叉复核：最大编码 6475 → ÷256 = **25.29 m**，与 DTOF 25 m 量程吻合；÷1000 只有 6.47 m，但图像有效深度区明显延伸到 15 m 以外的远端路面，÷1000 自相矛盾。
近端交叉复核：多数帧最小非零回波 **0.54~0.55 m**，正是图像底边附近的路面；与 `h=0.52 m`、底边射线俯角约 41°（0.52 / tan41° = 0.60 m）自洽。

**③ 语义 = 相机系 z-depth，不是径向斜距**
按 z-depth 反投影后，路面点的高度离散度仅 7.3% 且不随入射角发散；若存的是 range，直接当 Z 用会让近处地面被系统性抬高。导出链路 `rosbagbinpng.py` 写入的是 `camera_point.z`，本数据的量程与地面高度也同时与 z 语义自洽。

**④ 截断而非四舍五入（已知、可量化）**
`(clip(depth,0,255)*256).astype(uint16)` 是截断，单像素被低估 0~1 LSB，均值 **−1.95 mm**；在 1 m 处 −0.20%，20 m 处 −0.01%。

**⑤ 无 255 m 饱和**
最大编码 6475 « 65280，量程裁剪从未触发。

### 2.2 使用注意（编码没问题，但用错会全毁）

**风险 1｜读成 8 位 → 深度全毁。** 实测：

```
PIL Image.open            -> uint16  max=6443   ✅
cv2.imread(IMREAD_UNCHANGED) -> uint16  max=6443   ✅
cv2.imread 默认            -> uint8   max=25     ❌ 16→8 位被缩放 ÷257
```

必须写 `cv2.imread(path, cv2.IMREAD_UNCHANGED)` 或 `np.array(Image.open(path))`。

**风险 2｜`dense_depth` 不是逐像素深度。** 它的真实分辨率只有 **约 229×185**，被 7×7 块上采样存成了 1600×1296：

- 行/列游程直方图主峰 = 7 px（`fig05_depth_blocks.png` 可见完整块栅格）
- 后果：①有效深度分辨率只有 1/49；②深度"边缘"被量化成 7 px 台阶，任何基于深度的亚像素几何精度不可能优于 **±3.5 px**；③当逐像素深度真值用会产生块状伪影
- 块边界相位不与 7 的整数倍对齐（x mod 7 ∈ {1,2,3,4}），存在 1~2 px 亚格偏移

**风险 3｜`0` 是无回波，不是 0 米。** 天空 97.8%~100% 无回波，可通行区仅 2.6%~5.6%，不可通行区 30%~81%（近景障碍过近 vs 远景植被超量程）。**绝对不能把 0 参与深度回归**。另外，无效区的上边界主要由 **25 m 量程**决定而非图像内容 —— 因此**不能把"深度无效"当作天空/远景的语义监督**，否则会把 25 m 外的所有物体都标成天空。

## 3. 配准核查

### 3.1 RGB ↔ GT —— 准确

- **同源标注**：标签是在图像上勾出的多边形，二者天然同源。
- **排除"标签由深度派生"**：若标签由深度图派生，其边界会大量落在深度 7 px 块相位上。实测标签边界像素 `x mod 7` 分布 = `[718, 755, 742, 759, 805, 789, 758]`，**χ² = 6.5**（6 自由度，临界值 12.6@0.05）→ 与深度块相位**无关联**，是在图像上独立标注的。
- **贴合度**：标签边界处的图像梯度均值 4.54，全图均值 3.51，比值 **1.29**；边界到最近强图像边缘的中位距离 4~6 px。
- **无系统平移**：对标签做 ±10 px 平移扫描，最优点在 (−10, ±2)，改善仅 1~2 px，且方向在帧间不稳定 → 不存在一致的系统偏移。
- **但标注粒度粗**：标签是直线段拼成的多边形（`fig03`/`fig04` 清晰可见），未逐像素沿轮廓勾边；左侧帐篷等薄结构被整体并入"不可通行"。**边界精度约 ±3~8 px，不适合细粒度边界指标评测。**

### 3.2 depth ↔ RGB —— 无 ≥5 px 系统错位

- **目视证据（最有说服力）**：`fig06_overlay_tractor_near.png` 中，拖拉机轮胎的轮廓在深度图中清晰可辨，且与 RGB 中的轮胎重合。
- **定量证据**：取深度连通体轮廓，量它到最近强图像边缘的中位距离：

| 样本 | 轮廓点 | (0,0) 中位距离 | 最优平移 | 改善 |
|---|---|---|---|---|
| 817224311091（近拖拉机） | 1934 px | 5.00 px | 4.47 px @ (−8, 0) | 0.53 px |
| 681150656293（远拖拉机） | 2124 px | 4.00 px | 4.00 px @ (−8, −4) | 0.00 px |

零位移已在最优点附近，最优平移改善 <1 px 且帧间方向相反 → **无系统错位**。
- **精度上限**：受 7 px 分块量化限制，本方法分辨极限约 **±4 px**；更细的偏移用这批数据无法验证。

### 3.3 depth ↔ 标定几何 —— ⚠️ 垂直方向 ~18 px（≈1.4°）系统失配

这是本次核查发现的**唯一实质几何问题**。用了两条**互相独立**的证据，结论一致：

**证据 A｜地面点回归 `v = a + b/Z`**
水平地面理论上满足 `v = v0 + h·A22/Z`，故截距 `a` 应等于 `v0`（含俯仰修正），斜率 `b = h·A22`。

| 样本 | Z 区间 | a (px) | a − v0 | h (m) |
|---|---|---|---|---|
| 346035329872 | 0.7~3 m | 677.77 | **+20.1** | 0.522 |
| 346035329872 | 1~6 m | 677.33 | **+19.7** | 0.523 |
| 681150656293 | 1~6 m | 675.12 | **+17.5** | 0.523 |
| 817224311091 | 1~6 m | 674.52 | **+16.9** | 0.525 |

近场 0.7~6 m 的 `h` 稳定在 **0.522~0.534 m**（跨帧极差 <1.5 cm），说明深度与 K **在同一像素网格上高度自洽**；但外推出的地平线比 `v0 = 657.66` 高 **16~20 px**。

**证据 B｜25 m 量程线的位置（完全独立的另一条）**
逐列最上有效行的分布主峰在 **685~709 行**（192/400 列）：

- 按 `calib v0 = 657.7` + `h = 0.52 m` 推算，25 m 量程线应在第 **673** 行
- 按证据 A 的 +18 px 推算，应在第 **691** 行
- 实测主峰 **685** → 与 "+18 px" 一致，比 calib 预言高 **约 12 行**

一条用地形高度、一条用量程边界，两者同向同量级 → 不是拟合偶然。

**成因（本静态场景无法区分，可并存）**
1. 道路在 5 m 外有约 1.3° 纵坡；
2. 远端 GT 边界不精确，把路肩/植被算进了"可通行"（4~20 m 段 `h` 在部分样本抬升到 0.59~0.71 m 支持这一点）；
3. DTOF 距离相关偏差；
4. 标定俯仰/主点残差（与既往在同一 Odin1 导出链路上发现的"运行时 K ≠ 导出 calib"同向）。

**影响量化**
直接用 `calib.yaml` / `calib_1280x1088.yaml` 做深度→3D 提升而不重新拟合地面，会带 **~1.4° 系统倾斜**：水平面高度在 10 m 处偏 **约 25 cm**、20 m 处偏 **约 49 cm**。

**重要限定**：`main.py` 当前只用 RGB + 标签做分割，`dense_depth` 根本没进入预处理链 → **这个残差不影响现阶段的分割训练与评估**。只在把深度用于 BEV / 3D 提升 / 深度监督时才必须处理。

### 3.4 裁剪为 1280×1088 —— 完全正确

| 检查项 | 结果 |
|---|---|
| 裁剪框 | `crop_box_ltrb = (160, 104, 1440, 1192)`，与 `ExtCenterCrop.get_box((1600,1296))`、`main.py` 的 `ODIN1_CROP_SIZE_HW=(1088,1280)` **三方一致** |
| 派生 `u0` | 816.125795 → 期望 656.125795 / 文件 656.125795，**差 0.0e+00** |
| 派生 `v0` | 657.659526 → 期望 553.659526 / 文件 553.659526，**差 0.0e+00** |
| `A11/A12/A22` | 裁剪不缩放，保持原值 ✅ |
| 畸变 `k2~k7`、`Tcl_0` | 保持原值 ✅ |
| 三模态同步 | 25 帧 RGB / GT / depth 用同一框裁剪，逐像素 `array_equal` **全 True** |
| 内容损失 | 保留 67.2% 面积；可通行保留 66%~67%、天空保留 66%~70%，比例基本不变（裁剪框居中，未偏侧） |
| 几何等价性 | 原始 `h=0.5257 m / RMS=26.3 mm` vs 裁剪 `h=0.5251 m / RMS=24.5 mm`，**h 差 0.6 mm、RMS 差 1.8 mm** |

→ **裁剪口径无误，可安全使用 `calib_1280x1088.yaml`；深度若接入，必须复用同一个 `crop_box`，否则会错位 (160,104) px。**

### P4 的可直接使用修正片段

```python
# 在 wkb 内生成修正后的标定，不覆盖原文件
import yaml, copy, pathlib
src = pathlib.Path(r'...\segdataodin\calib_1280x1088.yaml')
cal = yaml.safe_load(src.read_text(encoding='utf-8'))
cal = copy.deepcopy(cal)
DV_PX = 18.0                      # 由地面回归 + 量程线两条证据得出
cal['cam_0']['v0'] += DV_PX       # u0 无法从本场景验证，保持不变
cal['cam_0']['ground_pitch_note'] = 'v0 shifted by +18 px per ground-plane refit'
out = pathlib.Path(r'...\wkb\audit_20261124\calib_1280x1088_v0fix.yaml')
out.write_text(yaml.safe_dump(cal, allow_unicode=True), encoding='utf-8')
```

> 注意：+18 px 是把"俯仰残差"折算成主点偏移的**等效**做法；若下游要接 BEV，更稳妥的是每批数据用路面点**在线重拟合**地面平面，而不是硬编码这个常数。

1. **深度编码正确**，`值 ÷ 256 = 相机系 z-depth（米）`，`0 = 无回波`，16 位无损，无饱和。四条独立证据（地面高度 0.52 m、25 m 量程、近端 0.54 m 路面、导出链路源码）互相印证。
2. **配准准确**：RGB↔GT 无系统平移；depth↔RGB 无 ≥5 px 错位（目视 + chamfer 双重确认）；裁剪 1280×1088 口径完全正确、几何等价。
3. **唯一实质几何问题是 depth↔标定约 1.4° 的垂直失配**，只在把深度用于 3D/BEV 时才有影响，用地面重拟合或 `v0 += 18 px` 即可消除。
4. **数据本身最大的短板不是编码或配准，而是场景重复**：25 帧其实是 1 个静止机位 + 1 台移动拖拉机，测试帧与训练帧相隔 0.29 s。在做任何精度结论之前，必须先扩充场景。
