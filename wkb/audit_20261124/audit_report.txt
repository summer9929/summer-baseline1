1. 深度编码核查
========================================================================================
[1.1] 容器与位深
    PNG mode=I;16  dtype=uint16  shape=(1296, 1600)  info={}
    -> 16 位单通道灰度，无调色板、无 alpha、无影响数值的元数据

[1.2] 读取方式陷阱（实测）
    PIL  Image.open -> uint16 max=6443   [正确]
    cv2  IMREAD_UNCHANGED -> uint16 max=6443   [正确]
    cv2  imread 默认 -> uint8 shape=(1296, 1600, 3) max=25   [错误：16->8 位被缩放 ÷257，深度信息全毁]
    -> 任何读取路径都必须显式保留 16 位，否则得到 0~25 的假值

[1.3] 量化粒度
    不同取值 1788 个，相邻最小间隔 1 LSB -> 满量程使用，低 8 位 256 种取值全部出现
    1 LSB = 1/256 m = 3.91 mm

[1.4] 尺度倍率：地面平面 + 量程 + 近端三重复核
    原理：路面点满足 Z*(v-v0)/A22 = h（相机离地高度常数）。缩放 Z 只改变 h 的绝对值。
    假设                h_中位(m)      h_p10      h_p90
    ÷256 (m)            0.565      0.510      0.605
    ÷512                0.283      0.255      0.303
    ÷1000 (mm)          0.145      0.131      0.155
    当 mm              144.741    130.561    154.923

    只有 ÷256 给出的 h=0.565 m 落在车载/农机传感器的合理安装高度区间；
    ÷1000 得 0.145 m（14.5 cm，不可能），当 mm 得 145 m（不可能），÷512 得 0.283 m（28 cm，偏低）。
    量程复核：最大编码 6475 -> ÷256 = 25.29 m，与 DTOF 25 m 量程一致；÷1000 仅 6.47 m，
    但图像有效深度区明显延伸到 15 m 以外的远端路面，÷1000 在物理上自相矛盾。
    近端复核：多数帧最小非零回波 0.54~0.55 m（÷256），恰为图像底边附近的路面，
    与 h=0.52 m、底边射线俯角约 41°（0.52/tan41°=0.60 m）一致。

[1.5] 编码语义：z-depth 而非斜距
    按 z-depth 反投影后，路面点高度离散度 CV=7.28%；若编码为径向斜距，
    需先做 Z=range*cosθ 换算，直接把值当 Z 会让近处地面被系统性抬高。
    导出链路 rosbagbinpng.py 写入的是 camera_point.z；本数据量程与地面高度也与 z 语义自洽。
    -> PNG/256 = 相机系 z-depth（单位 m）。

[1.6] 截断（floor）编码偏置
    (clip(depth,0,255)*256).astype(uint16) 是截断而非四舍五入，
    单像素被低估 0~1 LSB，均值 -0.5 LSB = -1.95 mm；1 m 处 -0.20%，20 m 处 -0.01%。
    建议读回用 PNG/256（与导出严格互逆）；若要无偏中点估计用 (PNG+0.5)/256。

[1.7] 分块上采样：dense_depth 的真实分辨率
    行 1200 游程长度直方图(0..15): [0, 0, 0, 0, 0, 0, 0, 127, 1, 0, 0, 0, 0, 0, 36, 2]
    -> 绝大多数游程 = 7 px；列方向同样为 7 px 台阶
    真实深度网格 ≈ 229 x 185（1600/7 x 1296/7），却被存成 1600x1296
    块边界相位：x mod 7 ∈ [1, 2, 3, 4]，y mod 7 ∈ [0, 1, 6]（非 7 的整数倍，存在 1~2 px 亚格偏移）
    影响：①真实深度分辨率只有 1/49；②深度"边缘"被量化成 7 px 台阶，
          基于深度的亚像素几何精度不可能优于 ±3.5 px；③当逐像素深度真值用会产生块状伪影。

[1.8] 无效值语义与分布
    编码 0 = 无回波（天空 / 超 25 m 量程 / 近距盲区），不是"0 米"。
    346035329872    天空无回波100.0%  可通行无回波5.6%  不可通行无回波81.0%
    817224311091    天空无回波97.8%  可通行无回波2.6%  不可通行无回波30.0%
    天空 97.8%~100% 无回波，可通行区仅 2.6%~5.6% 无回波 -> 语义自洽；
    不可通行区无回波比例在 30%~81% 间大幅变化（近景障碍过近 vs 远景植被超量程）。

[1.9] 可疑近距回波
    validation/820245930644: <0.30 m 像素 50 个（最大编码 73 = 0.29 m）
    validation/823657556154: <0.30 m 像素 2274 个（最大编码 70 = 0.27 m）
    validation/824047451735: <0.30 m 像素 519 个（最大编码 75 = 0.29 m）
    -> 仅出现在 3 个验证帧，成块出现（单帧 <0.30 m 像素最多 2274 个 ≈ 46 个深度块），
       疑为机具自身遮挡/多路径；数量极小（<0.2% 像素），不影响编码判断，但近距障碍检测需剔除。

       当前划分不具备场景独立性，验证/测试指标会明显偏乐观。

    全数据集只有 1 个机位：25 帧中 22 帧 RGB 两两相关 >0.98，其余 3 帧是同一机位下拖拉机驶近。
    等价于"1 个静态背景 + 1 个移动目标"，对 3 类分割训练而言场景多样性几乎为 0。

========================================================================================
6. 结论
========================================================================================
  【编码】正确。PNG 为 16 位单通道，值 = floor(z_depth_m * 256)，0 表示无回波，
     1 LSB = 3.91 mm，无 255 m 饱和。÷256 与"离地高度 0.52 m / 25 m 量程 / 近端路面"
     三者同时自洽；÷512、÷1000、当 mm 都会给出物理上不可能的安装高度。
     风险点：①读取必须保留 16 位（cv2.imread 默认会缩成 8 位，最大值从 6443 变 25）；
     ②编码是截断不是四舍五入，单像素平均偏低 1.95 mm；
     ③dense_depth 是 7x7 分块上采样，真实分辨率仅约 229x185，不是逐像素深度。
  
  【RGB<->GT 配准】准确。两者同源标注，标签边界处图像梯度为全图 1.3 倍，
     平移搜索最优改善仅 1~2 px 且方向帧间不一致 -> 无系统平移。
     但标注是粗粒度多边形，边界精度 ±3~8 px，不适合细边界指标评测。
  
  【depth<->RGB 配准】未见 >=5 px 系统错位。拖拉机轮胎轮廓在深度图中清晰可辨且与 RGB 重合
     (fig06)；轮廓 chamfer 在零位移处即最优附近，最优平移改善 <1 px 且方向不一致。
     受 7 px 分块量化限制，该数据的配准可验证精度约 ±4 px。
  
  【depth<->标定】存在需要关注的系统残差。近场 0.7~6 m 地面高度恒定在 0.522~0.534 m，
     但外推地平线比 calib.yaml 的 v0 高约 16~20 px（≈1.4°）。该偏差被两条独立证据复现：
     ①地面点回归截距 +16~20 px；②25 m 量程线实测在主峰约 695 行，比按 v0 推算的 673 行高 22 行。
     成因可能是道路纵坡、DTOF 距离相关偏差或标定俯仰/主点残差，本静态场景无法区分。
     影响：直接用 calib 做深度->3D 提升会带 ~1.4° 系统倾斜（水平面在 10 m 处偏 25 cm、20 m 处偏 49 cm）。
     建议：进 BEV 前用本批数据的路面点重新拟合地面/俯仰，或把派生标定的 v0 整体 +18 px 后再用。
     注意：当前 main.py 只用 RGB+标签做分割，此残差**不影响现阶段的分割训练与评估**。
  
  【裁剪 1280x1088】完全正确。三模态同框、派生 u0/v0 复算零误差、A11/A12/A22 不变，
     裁剪前后地面几何 h 差 <1 mm、RMS 差 <2 mm。可安全用 calib_1280x1088.yaml。
  
  【主要数据质量缺陷（非编码/配准问题）】
     1) 场景多样性几乎为 0：25 帧 = 1 个静止机位 + 1 台移动拖拉机；
        测试帧与某训练帧 RGB 相关 0.996（时间差 0.29 s），划分不独立，指标必然偏乐观。
     2) 深度 40%~56% 无回波；无效区上边界主要由 25 m 量程决定，
        不能把"深度无效"当天空语义监督用。
     3) 3 个验证帧存在 <0.30 m 的近距回波（最大 441 px 成块），疑为机具自身遮挡，近距检测需剔除。
     4) dense_depth 未接入 main.py 预处理链；接入时必须复用同一 crop_box。
